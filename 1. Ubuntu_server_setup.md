# ✅ Enable Virtualization

Virtualization must be enabled before creating virtual machines.

## Step 1

Restart your computer.

During startup, repeatedly press the BIOS key.

Common keys:

- `Delete`
- `F2`
- `F10`
- `Esc`

---

## Step 2

Navigate to the Virtualization settings.

Enable:

- **Intel VT-x (VMX)**
- **AMD SVM Mode**

Save using **F10** and restart.

---

## BIOS Settings by Manufacturer

| Manufacturer | BIOS Path |
|--------------|-----------|
| ASUS | Advanced Mode (F7) → Advanced → CPU Configuration → Intel Virtualization Technology / SVM Mode |
| Dell | Virtualization Support → Enable Virtualization |
| HP | Security → Virtualization Technology (VTx) → Enabled |
| Lenovo | Security → Intel Virtualization Technology / VT-d |
| MSI / Gigabyte | Overclocking → CPU Features → SVM Mode or VT-d |

## SSH Troubleshooting Commands

## Verify the VM IP Address

```bash
hostname -I
```

## Check OpenSSH Server Installation
- Check OpenSSH Server Installation
- Install it again to try if there is a miss match in installation.
```bash
dpkg -l | grep openssh-server
sudo apt update
sudo apt install openssh-server -y
sudo systemctl enable --now ssh
sudo systemctl status ssh --no-pager
```
- Start and Enable SSh again
```
sudo systemctl enable --now ssh
sudo systemctl status ssh --no-pager
```
- Confirm SSH Is Listening on Port 22
```
sudo ss -tlnp | grep ':22'
```
- outut to confirm its listnening
***0.0.0.0:22[::]:22***
- Validate SSH Server Configuration
```
sudo sshd -t
sudo sshd -T | grep -E 'port|listenaddress|passwordauthentication|permitrootlogin'
```
- Check SSH Logs
```
sudo journalctl -u ssh --no-pager -n 50
```
- Live monitoring:
```
sudo journalctl -fu ssh
```
- Test SSH Locally Inside Ubuntu, exit the session:
```
whoami
ssh ubuntu@localhost
exit
```

- Check Ubuntu Firewall
```
sudo ufw status
```
- Allow SSH if UFW is active:
```
sudo ufw allow OpenSSH
sudo ufw reload
```
- Test Network Connectivity from Windows
```PowerShell
ping 192.168.80.128
Test-NetConnection 192.168.80.128 -Port 22
```

## SSH Connection Failure Caused by VPN

The Windows host could not reach the Ubuntu VM over the VMware NAT network. SSH returned Windows socket error `10013`, and ping returned `General failure`.
The root cause was Proton VPN, which was blocking or rerouting traffic to the private VMware subnet `192.176.90.0/24`.
Resolution:
1. Disconnect Proton VPN.
2. Verify host-to-VM connectivity.
3. Connect using:
```powershell
ssh ubuntu@Ip_address
```
